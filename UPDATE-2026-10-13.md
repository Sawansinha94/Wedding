# Wedding Concierge update — 13 October 2026

## Implemented
- Name matching supports exact full names, first names, aliases, and spelling variations; near-equal results return an ambiguous shortlist instead of guessing.
- Name matching runs against the private server-side roster; Pinecone remains available for separate diagnostics. A name or trivia response is NOT authentication.
- Familiarity question answers accept partial words of at least 3 characters and fuzzy variations. They are low-assurance only.
- Concierge has stronger instructions to lead conversation and ask a warm follow-up, without pressuring guests.
- Floating greeting supports ambiguous-name status, in addition to confirmation, question and ready.
- More offline translation entries; `window.weddingLanguage.coverage()` reports translated count in the current page. Missing strings still rely on the existing translation endpoint, so full instant coverage is NOT complete.
- Removed only generated Python cache files; no potentially needed application scripts or assets were deleted.

## Important checks
1. Set `CONCIERGE_SIGNING_SECRET` (random 32+ characters) in `.env`, never commit credentials.
2. Run `python -m compileall -q backend` and `node --check assets/js/02-features.js`.
3. Start `uvicorn server:app --reload --port 8000`.
4. POST `/api/profile/start` with `{"name":"Sujata"}`; expect confirmation if unambiguous.
5. Test ambiguous first names; response should contain a shortlist.
6. Test confirmation and familiarity question; confirm private profile details are not leaked.
7. Open DevTools Console and run `weddingLanguage.coverage()` after switching language. Untranslated strings indicate remaining catalog work.
8. Check `wedding_system_logs` events and inspect failures; live DB logging was not tested here.

## Not completed
- Complete manually reviewed static translations of every page.
- Live browser, Neon, Pinecone, Bedrock and voice end-to-end tests.
- Advanced automatic proactive messages after long inactivity.

## Privacy
The master JSON contains private guest details. Keep the backend and the ZIP private. Do not publish it as a static hosting directory or expose `data/private` via web routes. Rotate previously shared credentials.
